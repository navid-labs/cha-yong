## 한 줄 결론

자승카는 네이버 카페 그 자체가 서비스다 — 게시판이 매칭 엔진이고, 운영자는 "승계 대행"과 신차 입점광고로만 수익을 노린다(금액은 로그인 벽 뒤). 승계고는 겉보기엔 완전 무료 직거래(계산기까지 포함)지만, **2026-09-04 공식 공지로 "승계 대행 서비스"를 9월 중 유료 출시 예고**했고, 모회사 주식회사 렌트야는 같은 도메인(sggo.kr) 위에서 "렌트야 플러스"라는 딜러(대리점) 네트워크로 신차 장기렌트 견적을 이미 팔고 있다 — 승계 무료 트래픽이 신차 견적 퍼널로 흘러드는 구조가 코드와 내비게이션에 그대로 보인다. 승계고의 지원금 계산기는 **잔여 렌트료 총액과 잔존가치의 합에서 중고차 시세를 뺀 값의 1/3**을 지원금/인도금으로 제안하는 독자 산식이며(§승계고 8), 매물 설명란에 매도자 휴대폰번호를 그대로 노출한다(§승계고 4·9) — 차용의 연락처 차단 정책과 정면으로 다른 방식이다.

기존 문서(`2026-09-15-competitor-landscape.md`) §1.1의 "승계고 커뮤니티 안내 공지 2026-08-31 (오픈 초기 추정)"은 **서비스 자체에 한해 정정이 필요하다**: `/about`의 자기소개("승계GO는 **2014년 출범**") + 공식 공지 "'승계고'는 어떤 서비스인가요?"(**2023-12-18**, 서비스 정의를 그때 이미 공지)를 보면 승계고 서비스는 최소 2023년부터 운영 중이었다. 다만 "2026-08-31 커뮤니티 이용 안내"는 별개 주장이다 — **커뮤니티 게시판(`/community`) 자체는 신형 Vue SPA 출시와 함께 새로 열렸을 가능성**이 있어, 이 글이 "신규 게시판 안내"인지 "재게시"인지는 미확인이다(§10 참고).

# 자승카 — https://cafe.naver.com/wowowowowow

카페 특성상 매도자 여정(2)·매물 데이터 필드 표(4)·거래 흐름(5)·앱과 웹의 기능 차이(6)는 **해당 없음/비공개**로 둔다. 게시글 본문과 등록 폼은 실명 확인 후 가입한 회원만 볼 수 있어 확인할 수 없다.

## 3. 인수자 여정

①실명 확인 후 카페 가입 → ②"▩ 승계 거래" 카테고리에서 국산차/수입차 승계, **맞승계'만' 전용 게시판**(차량 맞교환), **저신용자 전용(렌트,리스)**, 기타거래 중 탐색, 또는 "💌 승계 차량 추천받기" 카카오채널로 요청 → ③마음에 드는 매물 글에 댓글/쪽지로 매도자와 직접 연락(카페 자체 "채팅" 메뉴가 있으나 매물별 전용 채널인지는 미확인) → ④매도자와 지원금/인도금·잔여조건 직접 협의 → ⑤렌트사·캐피탈사 승계 심사(카페 밖 절차) → ⑥명의 변경 완료. [판단] 카페는 탐색·매칭 이후 개입하지 않는 것으로 보인다(에스크로·결제 UI 없음).

**수요 신호** — 사이드바 "최근 댓글·답글" 위젯에서 확인한 최근 게시글 제목([확인], 2026-09-15 스냅샷, 개별 게시글 열람은 로그인 필요라 목록 열람 못함, 이 위젯 텍스트만 공개):

- "26년 테슬라 모델3 퍼포먼스 렌트 맞승계"
- "[전차종맞승계]cle200 카브리올레 월109만원"
- "봉고, 포터 차량 승계 받고 싶습니다.~!"
- "팰리세이드LX3 7인승 가솔린 캘리 월82 맞승계 구합니다 (싼타페 하브 대환영)"
- "GN7 그렌저 하이브리드 1.6 맞승계 합니다."
- "잔여 기간 & 잔존가치 낮은 gv80, gle 가솔린 차량 승계 원합니다!"
- "[월71만]싼타페 하브 6인승 캘리 장기렌트 맞승계합니다."
- "장기렌터카 승계절차 문의드립니다."

"맞승계"(차량 대 차량 맞교환) 요청이 눈에 띄게 많고 전용 게시판까지 있다 — 단순 지원금/인도금 거래가 아니라 **승계 대 승계 물물교환** 수요가 상당하다는 신호다 [판단].

## 6. 앱과 웹의 기능 차이

앱스토어 검색("승계고 sggo 앱", "렌트야 앱 플레이스토어")에 승계고/렌트야 전용 앱이 나오지 않는다 [판단, 검색 결과 기반]. 웹은 Vue 3 SPA(반응형, 모바일 뷰 확인)이고, 구형 gnuboard 기반 "렌트야 플러스" 하위 경로(`/bbs/*`, `/estimate`, `/dealer`)가 같은 도메인에서 공존한다 [확인, 코드/네비게이션 관찰]. 앱이 없으므로 "차이" 항목은 사실상 해당 없음.

## 7. 검증·신뢰 장치

- 매물 상세의 사고유무·옵션·차량상태는 전부 **매도자 자기 신고(self-report) 텍스트**이고, 제3자 검증 배지·평가 점수·진단 리포트가 없다 [확인, 상세 페이지 관찰].
- FAQ가 사용자에게 직접 "승계 진행하기전 카히스토리 등으로 사고 이력을 조회"하라고 안내한다 — 플랫폼이 검증하지 않고 인수자에게 셀프 체크를 떠넘기는 구조 [확인, 원문 인용].
- 지원금 계산기가 "적정 금액"을 제시함으로써 바가지(과도한 인도금 요구, 부당한 지원금 요구)를 줄이는 간접적 신뢰 장치 역할을 한다 [판단].
- 커뮤니티 게시판("승계궁금해요")에서 동료 사용자 조언을 구할 수 있다 [확인].
- 에스크로·안전결제 없음 [확인, 결제 UI 부재].

**지원금 계산기 산식** (별도 도구, 결제와 무관 — (a)의 "현재 무료" 항목에 포함) [코드, `/assets/index-cd970476.js` 정적 분석]

입력(전부 사용자가 직접 입력, 만원 단위): 계약종료일(`endDate`), 월렌트료(`monthlyRent`), 보증금(`deposit`), 잔존가치(`residualValue`), 중고차시세(`marketPrice`, 엔카·헤이딜러 링크로 사용자가 직접 조회).

```
remainingMonths = 오늘부터 endDate까지 개월 수 (KST 기준)
residualVehicleValue = monthlyRent × remainingMonths + residualValue   # "계속 타면 만기까지 낼 총액 + 잔존가치"
diff = residualVehicleValue − marketPrice   # 잔여계약가치가 중고시세보다 얼마나 비싼가/싼가

diff > 0 (계약이 시세보다 비쌈) → subsidyAmount = round(diff / 3), 최소 1만원
diff < 0 (계약이 시세보다 쌈)   → takeoverReferenceAmount = round(-diff / 3), 최소 1만원

finalAmount:
  diff > 0 → deposit − subsidyAmount           # 보증금에서 지원금 몫을 뺀 나머지
  diff < 0 → deposit + takeoverReferenceAmount # 보증금에 인도금 몫을 더함
  diff = 0 → deposit

결과 표시:
  finalAmount > 0 → "인도금 {finalAmount}만원이 적정해 보여요"
  finalAmount < 0 → "지원금 {|finalAmount|}만원이 적정해 보여요"
  finalAmount = 0 → "지원금 없이도 거래가 가능해요"

보조 안내 문구(보증금 입력이 있을 때) [코드, 원문]: "인도금(지원금)에 보증금이 포함되어 있어요"
  — 즉 보증금은 별도로 얹는 금액이 아니라 인도금/지원금 산정의 기준선(base)이라는 뜻이다.
```

핵심 아이디어는 **"잔여계약 부담 대비 시세 차이의 1/3"**을 지원금/인도금 기준선으로 잡고, 보증금(만기에 돌려받거나 인수 비용에 충당할 금액)을 그 위에 가감하는 것이다. 카딩처럼 실거래 변동이력을 누적하는 방식이 아니라 **순수 계산식**이다 — 차용의 `calcTotalAcquisitionCost`/`calcTotalEffectiveCost`(단순 합산)와는 접근 자체가 다르다.
